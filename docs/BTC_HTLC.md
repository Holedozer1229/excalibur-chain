# Bitcoin HTLC transactions

AetherionEXCAL can create, sign, and broadcast Bitcoin HTLC funding, claims,
and refunds through a configured Bitcoin Core node. Every broadcast requires
an explicit confirmation displaying the destination, amount, and estimated
fee. BTC funds are real and Bitcoin transactions are irreversible.

Configure Bitcoin Core RPC before using the BTC lock, claim, or refund actions:
The Atomic Swap tab includes a node setup panel for the RPC URL, network,
loaded wallet name, cookie-file path, and optional RPC username/password.
Settings except the password are saved locally in the wallet's application
settings directory; the password stays in memory for the current session.
Use the cookie file where possible. Select `main` only for production Bitcoin.

- `AETHERION_BTC_RPC_URL` (optional; defaults to `http://127.0.0.1:8332`)
- `AETHERION_BTC_RPC_COOKIE_FILE` (recommended), or both
  `AETHERION_BTC_RPC_USER` and `AETHERION_BTC_RPC_PASSWORD`
- `AETHERION_BTC_NETWORK` (optional; defaults to `main`; supports `test`,
  `signet`, and `regtest`)
- `AETHERION_BTC_RPC_WALLET` (required for funding; names a loaded, funded
  Bitcoin Core wallet that can create and sign PSBTs)

Before any network operation, the RPC client checks both Bitcoin Core's chain
name and `getblockhash(0)` against the canonical genesis hash for the selected
network. For mainnet, the expected hash is
`000000000019d6689c085ae165831e934ff763ae46a2a6c172b3f1b60a8ce26f`.

Use the cookie file generated by Bitcoin Core rather than putting credentials
in source code or command history. Remote RPC connections must use HTTPS. BTC
funding is created and signed by the selected Core wallet. BTC claims and
refunds are signed locally with the unlocked AetherionEXCAL wallet key, which
must match the corresponding HTLC branch key and payout address. The node must
have transaction indexing enabled (`txindex=1`) to locate confirmed funding
transactions that are not in its wallet. Restart Bitcoin Core and allow the
transaction index to finish syncing after changing this setting.

Fetch the current height from the configured node when creating an offer. The
BTC funding action previews the Core wallet's fee, signs and broadcasts the
transaction to the exact HTLC address, and waits for confirmation before
recording the lock. Claim and refund actions show a fee estimate and payout
before signing and broadcasting; the follow-up verification button records the
spend after confirmation. Claims spend the recorded output and reveal the swap
preimage in the HTLC witness. Refunds use the refund branch only after the
configured block timeout. Check the displayed network, payout address, amount,
and fee before confirming.

The hash lock uses SHA-256 and its preimage comes from the operating system
CSPRNG. This does not make Bitcoin's secp256k1 signature system quantum-safe;
the BTC signatures remain subject to the security of Bitcoin's current
signature scheme.
